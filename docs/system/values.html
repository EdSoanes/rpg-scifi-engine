Values

Every number on the sheet explains itself and can be changed where it stands. The marks, three depths of explanation, four ways to change a value, rolls and judgements in progress, and the list of what was changed by hand. Concept, not prototype.

The principle

Tap a number to see why. Change it from there.

Every number, dice expression, word and pip on the sheet is one kind of thing: a value. Tapping any value explains it in the detail panel. Every way of changing it lives in that explanation. There is no edit mode, no settings screen and no second place to look.

  • The sheet behaves like pencil on paper. The GM can change any number, cancel any bonus, add one nobody wrote down, or simply call a result. The sheet records it and does not argue.
  • A change by hand is a full citizen. Everything that depends on it updates, it is marked where it shows, it says who made it and why, and it can be taken back.
  • The rules' own number never disappears. A value set by hand shows what the rules would have said beside it.
  • Most players never look past the number. The working is there, one tap at a time, for whoever wants it.
Why one component for every value

If a rating, a difficulty, a dice expression and a duration each had their own editor, a player would need to learn four places and a GM would need to know which one applies before they could say "just make it sixteen". One component, one tap, one panel means the answer to "how do I change this?" is always the same: tap it.

Marks

Five marks say how a value got there, at a glance

A value with no mark is exactly what the rules say. Anything else carries one small mark. The marks are the same everywhere: on a stat, a pip, a chip, a term in a roll, a bar in the ledger.

The marks
MarkMeansNotes
DotChanged by hand somewhere in its working.Wins over every other mark, because it is the one a table argues about. A value derived from a hand-changed value carries the dot too, so a hand change is never hidden one level down.
Up caretAbove its lasting value for now.A stim, a bonus for this roll, a state. Goes when the effect ends.
Down caretBelow its lasting value for now.A wound, a stun, a degraded item, pips spent.

  • A value can carry the dot and one other mark. Two carets cannot both apply; the net direction shows.
  • The marks use no pool colour. The dot is the accent colour; the underline is the warning colour; carets and dashes are ink.
Why so few marks

A sheet full of coloured badges stops being read. Five marks answer the three questions a player has about a number they did not expect: did someone change it, is it temporary, and is it finished. Everything else is in the explanation.

Three depths

  • The explanation always fits the detail panel without scrolling for a typical value: up to six contributions. More collapse into "and 3 more", one tap to open.
  • The working opens one level per tap. It is never shown all at once.
  • Selecting another value replaces the panel's content. The panel keeps a short back trail, so following a contribution to its own source and back is two taps.
Why the sentence comes before the numbers

"Eleven: your Firearms, your pistol training, your gear, the stim, and two the GM gave you for the position" answers the question most players actually ask. The bar shows proportion at a glance. Only someone who wants the arithmetic needs the rows, and only someone checking the rules needs the tree.

The explanation

  • Header: what the value is, and in a few words what it is for. "Added to 2d10 when you shoot." No rule names.
  • Value: large, with its mark. If set or adjusted by hand, the rules' value sits beside it: "rules say 9".
  • Sentence: the contributions in words, biggest first, hand changes last and named as such.
  • Bar: one segment per contribution, width by size. Lasting parts are grey, temporary parts are accent, hand changes are hatched. Penalties hang below the line. Something set aside shows as a dashed outline where it would have been.
  • Rows: one per contribution: name, amount, origin in words, how long it lasts, and one control.
    • A switch on anything that can be set aside: gear, a state, an effect. Switching it off is a hand change.
    • A cross on a hand change, to take it back.
    • Nothing on what the character is: a skill or an attribute. Those change with Set or Add.
    • Tapping a row's name opens that contribution's own explanation, with a back trail.
  • What does not count is listed, struck through, with the reason in words. A player can see the laser sight is wasted.
  • Buttons: Set, Add, Back to rules (only when something was changed by hand), Show the working.

Changing a value

Four verbs, and they mean the same thing everywhere

Set it to a number. Add to it. Set a contribution aside. Put it back to what the rules say. Every change by hand is one of these four.

The four verbs
VerbThe GM saysWhat happensEngine
Set"Your Health is 12." "Just make it sixteen."The value becomes that number. The rules' value stays visible beside it. Contributions still show, marked as set aside by the change.Override by hand
Add"Plus two for the smoke." "Take one off for the noise."A new named contribution, hatched, with how long it lasts.Adjust by hand, with a name and a lifespan
Set aside"The stim doesn't help here." "Forget the cover."One contribution stops counting, struck through, with "by hand" as the reason. Asks once: here only, or the source everywhere.Switch the state or item off by hand; a single mod needs a switch of its own
Back to rules"Scrap that."Every hand change on this value goes. One at a time is the cross on its row.Undo the changes made by hand on the value
  • The pad opens in the detail panel in place of the explanation. Nothing else on the sheet is covered; the turn, the pips and the ledger stay live.
  • Set to starts at the current value. Add starts at 0. The stepper is for the common case of one or two; the keypad is for "make it 22".
  • Why defaults to GM call, because that is most of them. The reason becomes the change's name everywhere it shows.
  • How long defaults to the shortest sensible lifespan: this roll for a value in an action, until removed for a value of the character. The words are the sheet's usual durations.
  • Result shows the value before and after, and the odds word for any action it changes. After applying, the sheet briefly outlines every other value that moved, and the panel lists them: "Also changed: Defence floor, odds on 3 actions".
  • Applying is immediate and undoable. There is no "are you sure".
  • Expert shortcut: a long press on any value opens the pad directly, skipping the explanation.
Why the reason and the duration are asked every time

A hand change without a reason is the "number with no explanation" the transparency rule calls a defect, just made by a person. Two default chips cost no taps when accepted, and they are what makes the list of changes readable three sessions later. The duration matters because a GM's "+2 for the smoke" should not still be there next week.

Rolls and judgements in progress

Every term of a roll is a value. So is the result.

A roll in progress is laid out as its terms: the dice, the rating, the difficulty. Each is a value with its marks and its explanation. The result and the band it lands in are values too, and the GM can call them.

What can be done to a roll
ControlThe GM saysWhat happens
A term"Difficulty's eighteen, it's darker than you think."Tap the term: its explanation, with Set and Add. Same pad as any value.
Change the dice"Roll a d20 for this one."The dice term set by hand. The pace's dice stay shown beside it. Any whole-sum expression is accepted.
Type the dice"I rolled eleven."The dice result, not the total. Bonuses are added by the sheet.
Redo the roll"Roll that again."Clears the dice and asks again. The old result is kept in the working, struck through.
Call it"Call that a strong hit."The band set by hand. Everything the band drives follows: damage step, location choice, time saved.
Skip the roll"You just do it."No dice. The GM picks the band. The same as the certainty rule, by fiat, and marked as such.
  • Changes to a roll last for that roll unless the pad says otherwise. They do not leak into the next shot.
  • A change after the result has been used, such as calling a hit after damage was applied, offers to redo the steps that used it. It never redoes them silently.
  • Incoming numbers work the same way. The four slots of an incoming hit, a reaction total typed from across the table and the target panel's numbers are all values with the same pad.
Why "call it" is a first-class control

At a paper table the GM's most common ruling is not a number, it is a verdict: "that works", "near miss", "you nail it". Making the band itself changeable lets the sheet follow the GM's word without anyone reverse-engineering a modifier to land on it.

The working

  • Each line is a contribution: its amount, its name, and its origin in words: your skill, an item and its slot, a state with its turns, an action and its step, a change by hand with its reason.
  • A calculation shows what went in, what came out and the rules author's one-line description of it: "three bonuses, +3, stop at +2".
  • Things that do not count stay in the tree, struck through, with the reason: expired, not started, switched off, set aside by hand, over a cap, replaced.
  • Inside turn tracking, effects that have ended are still shown with the turn they ended. Outside it they are gone, and the working says "history is not kept outside counted turns".
  • Every line can be tapped to open its own explanation, with the same controls. The working is a way to find a value, not a separate editor.

Seeing what was changed

  • Badge: the turn strip shows a count of changes by hand, next to the pending rolls count. Tapping it lists them in the detail panel, newest first, with when, what, how much, why, and Undo.
  • The list includes everything done by hand: values set or adjusted, contributions set aside, states switched on or off, results called, rolls skipped, durations changed.
  • Show on sheet: a lens. While on, every value with a hand change is outlined and everything else is dimmed. For the GM asking "what have you changed?"
  • Ledger: a change made during turn tracking shows as a dot on its turn's column, so the timeline shows when the table stepped outside the rules.
  • Going back: going back to a turn forgets the changes made after it, and the confirmation lists them, as it already lists actions and rolls.
  • Changes that last (a house rule on Health) are kept with the sheet and survive saving and handover. A handed-over item carries its hand changes and their reasons.

Limits and warnings

  • A value outside a limit the rules know about carries the underline. Its explanation says which limit and why, in words: "Rating 9 · the human ceiling is 8 · allowed".
  • The pad never refuses a number. It shows the limit beside the result line and applies anyway.
  • A value set by hand stays set until it is taken back, even when its contributions change underneath it. The rules' value keeps moving beside it, so the table can see the two drift apart.
  • The only question the sheet asks is when a change cannot be cleanly taken back, such as calling a result after its damage was applied. The question names what else will change.

What it needs from the rest

  • Engine, exists: describe a value, an action, a state and an object; override and adjust by hand with the mark; list hand changes; undo one; switch states and sets by hand; a name on a mod; lifespans on mods.
  • Engine, small: switch a single mod off by hand, so one contribution can be set aside without switching off its source.
  • Engine, small: change a mod's lifespan by hand, for "one more turn".
  • Engine, small: put state switches made by hand in the same list as value changes. Already a listed gap.
  • Engine, small: undo the hand changes on one value, or all of them, as a group. Already a listed gap.
  • Engine, medium: when a value used by a finished step changes, report which steps used it, so the sheet can offer to redo them. Already a listed gap.
  • System: the band of an action's outcome is a value the outcome step reads, so it can be called by hand.
  • Sheet: the explanation, the pad, the marks, the lens and the badge. None of it needs another device.

Still open

Open: house rules that apply to everyone

A hand change belongs to one value on one sheet. A table that decides "Health is 12 + 2 × Body here" is changing a rule, not a value, for every character. Whether that is a sheet setting, a content edit, or simply a hand change on each sheet is not decided.

Open: changes without the GM

The sheet cannot tell a GM's change from a player's, and the vision says it never refuses. Whether a table can choose a softer guard, such as a hand change made with "Me" as the reason showing in a different weight, is not decided.

Open: words in the working

The working uses plain words built by the engine. Whether it should ever show the engine's own kinds (base, override, temporary) for a rules author, behind a setting, is not decided.
